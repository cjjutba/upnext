# upnext v1.1 design spec

Date: 2026-08-27
Status: approved (CJ picked stars, four modes with split toggle, monochrome
court). Delta on top of `2026-08-26-upnext-open-play-design.md`; everything
not mentioned here is unchanged. Reference product: pickleq.app (screenshots
reviewed 2026-08-27).

## 1. Matching modes (replaces "House rule")

The label "House rule" becomes **Matching mode** everywhere. Four modes:

| Mode | Badge | Finish tap | Rotation |
|---|---|---|---|
| Balanced | RECOMMENDED | one tap, all four off | rest first, rating balanced pairing |
| Social mix | | one tap, all four off | rest first, repeat avoiding pairing |
| Classic queue | | one tap, all four off | today's all-off, positions 1 and 3 vs 2 and 4 |
| Winners | | tap the winning pair | today's winners-stay, with settings |

The Winners mode card carries two settings: the existing win cap stepper and
a **Split winners** toggle. Split off = template `winners-stay`; split on =
template `winners-split`. Both existing template ids keep their exact
semantics, so old logs replay byte-identically.

New template ids: `balanced` and `social`. Their reducer behavior on
`game-finished` is identical to `all-off` (all four to the back in lineup
order, streaks reset). `winnerPair` is not required for them. The event
schema version stays 1; this is an additive union extension.

### Fairness rule (deliberate, differs from PickleQ)

In every mode, the four players of a new game are ALWAYS the first four
eligible players in queue order. The paddle-rack promise (longest waiting
plays next) is never traded away. A mode only decides the PAIRING of those
four, choosing among the three possible partitions:

- `[[a,c],[b,d]]`, `[[a,b],[c,d]]`, `[[a,d],[b,c]]` where a,b,c,d are the
  front four eligible.

Mode pairing selection:

- **Balanced**: minimize `|ratingSum(teamA) - ratingSum(teamB)|`; tiebreak
  by fewest repeat partnerships this session, then fewest repeat opponent
  meetings, then partition order. Unrated players count as 3.
- **Social mix**: minimize repeat partnerships this session; tiebreak by
  fewest repeat opponent meetings, then partition order. Ratings ignored.
- **Classic queue**: partition `[[a,c],[b,d]]` always, plus the existing
  exactly-four rotation via pairingCycle.
- **Winners**: unchanged winners-stay/split logic (winners at queue front
  drive the next lineup).

Repeat counts derive from `state.finishedGames` plus active games: a
partnership is an unordered player pair on the same team; an opponent
meeting is an unordered pair on opposite teams.

## 2. Player ratings and editing

`Player` gains `rating?: number` (integer 1 to 5, absent = unrated, treated
as 3 by Balanced). Roster data, not events; no Dexie schema version bump
(unindexed field).

The roster screen gains an **Edit players** toggle. In edit mode, tapping a
chip opens an inline editor: rename input and five star buttons (tap star N
sets rating N; tapping the current rating clears it). Saving updates the
player row (updatedAt bumps, so import merge stays last write wins). Chips
show the rating as a small `3*`-style suffix when set, using a star glyph
from Lucide, never an emoji. This also delivers the v1.1 "player rename"
candidate; the free-form level field stays on the type but is superseded by
rating.

## 3. Roster bulk actions

- **Check in all**: ghost button beside the Roster heading; selects every
  roster player (setup screen selection state). A "Clear" ghost button
  appears when any are selected.
- **Returning players**: when the roster has players who attended the most
  recent ended session and are not yet selected, show a quiet section:
  "Returning players (N)" listing their names with one **Check in
  returning** button that adds exactly those to the selection. Attendees =
  distinct playerIds with an effective `player-checked-in` in that session's
  log.

## 4. Live session additions

- **Mode dropdown** in the board header replacing the cycle badge: a button
  labeled with the current mode opens a menu (menu shadow token, modal
  radius) listing the four modes with one-line descriptions and the
  RECOMMENDED badge on Balanced; Winners row includes the win cap stepper
  and Split winners toggle. Picking one dispatches `rule-changed`.
- **Add court**: ghost button near the courts grid header. New event type
  `court-added {}` (envelope v1): reducer increments `courtCount`. The
  command triggers an auto-fill afterward. Courts are only ever added, never
  removed; closing covers taking one out of service.
- **Add player mid-session**: the check-in panel gains the same add-player
  input as the roster screen; submitting adds to the roster AND dispatches
  `checkInPlayer`, so a walk-up lands at the back of the queue immediately.
- **Up next preview**: under the queue header, when four or more eligible
  players are waiting, show the pairing the current mode would form next
  ("A + B vs C + D") as a quiet preview row. It is exactly
  `nextLineup(state, null)` rendered; no new logic and no event until a
  court actually opens.

## 5. Court card redesign

- **Minimal timer**: the huge center timer is gone. Elapsed time renders in
  the card header row, mono 16px, next to the status badge.
- **Court graphic**: a monochrome pickleball court drawn portrait with true
  line geometry from the 20x44 dimensions: outer boundary, net across the
  middle (a thicker line), kitchen lines at 7/44 of the length on each side
  of the net, and centerlines from each baseline to its kitchen line. White
  surface (`--bg`), lines in `--gray-1000` (net) and `--gray-500` (court
  lines), 1px except the net at 2px. Rendered as an SVG with
  `viewBox="0 0 20 44"`, height capped around 280px, centered in the card.
- **Names on court**: team A's two names stacked inside the top half, team
  B's inside the bottom half, centered in each service area, Geist 600,
  sized to fit (13 to 15px), never overflowing the court. The "vs" divider
  and the big pair headline are gone; the court IS the display.
- Winner buttons (Winners mode) keep pair names but read "Top pair won" /
  "Bottom pair won" ordering top/bottom to match the court halves; the
  all-off finish button and Swap partners stay below the court.

## 6. Routing and date

Hash routing with no new dependency: `#/setup`, `#/board`, `#/summary`.
Back and forward work; a direct load of `#/board` with no live session
redirects to `#/setup`. The resume flow navigates by setting the hash. The
setup header shows the live current date (formatted like the history rows)
next to "Open play".

## 7. Compatibility and non-goals

- Old event logs replay unchanged; new events (`court-added`) and template
  ids (`balanced`, `social`) are additive. Imports of v1 exports work.
- The reducer's unknown-event default already no-ops, so a v1 build reading
  a v1.1 log degrades gracefully rather than crashing.
- Not in this wave: skill-separated queues, dual winners/losers queues,
  mixed doubles, king of the court, scores, multi-device.
